Agent Flows & Multi-Device Architecture

사용자가 zkTalk 채팅창에 명령을 입력하면, 그 명령이 어떤 경로를 거쳐 어느 컴퓨터의 Agent에게 전달되고, 결과가 다시 돌아오는지를 시각화합니다. 커맨드 문법, 권한 체계, 오프라인/타임아웃 처리까지 한 장에 담았습니다.

1 · Agent Command Flow (happy path)

사용자 입력 → 결과 렌더까지

Agents 탭이나 Agent 전용 채널, 혹은 일반 채널에서 /device.agent command를 입력하면 다음 경로를 탑니다.

sequence · user → api → device → agent → back

실패 경로

① 디바이스가 오프라인이면 API가 3초 안에 device.offline 에러 응답 → UI는 “device asleep — Wake-on-LAN?” 버튼 노출. ② Agent가 timeout(기본 30s)이면 부분 출력 + ⏱ timeout 배지. ③ 권한 스코프 밖이면 403 scope_denied, UI는 "확장 스코프 요청하기" 바로가기.

스트리밍 렌더

stdout은 WS 이벤트로 청크 단위 수신. UI는 mono 버블에 append만 하고, stderr는 같은 버블 안에서 빨간 글자로 분리. 긴 결과(>1.5k 줄)는 자동으로 접힘 + “파일로 저장” 액션 제공.

3 · Multi-Device Architecture

한 사용자 + 여러 컴퓨터 + 팀 공유

zkTalk은 각 사용자가 여러 컴퓨터에 설치하고, 그 컴퓨터의 Agent들을 개인 DM 수준에서 호출하거나 커뮤니티와 공유할 수 있어야 합니다. 아키텍처 핵심은 ① 디바이스 식별·서명 ② 사용자 소유(private) vs 커뮤니티 공유(shared) 분리 ③ 모든 명령의 감사로그.

architecture · client · server · agents

Private vs Shared 디바이스

기본은 private: 소유자만 사용. 커뮤니티에 share하면 특정 역할만 호출 가능. 팀의 ci-machine, gpu-box 같은 장비를 이 방식으로 등록. 공유 시 허용 명령 화이트리스트와 승인 정책을 반드시 설정.

감사로그 & 재실행

모든 명령은 Command Ledger에 append-only로 남음. Device Dashboard의 "최근 실행" 테이블은 여기를 읽음. 같은 명령을 다시 누르면 서명 확인 후 재실행; 실패한 명령은 같은 입력으로 즉시 retry 제공.

오프라인 처리

디바이스가 offline이면 명령은 queued 상태로 Ledger에 저장. 디바이스가 다시 heartbeat을 보내면 UI에 "대기 중이던 N개 명령이 있습니다 — 실행/취소" 알림이 뜸.

보안 경계

각 디바이스는 설치 시 디바이스 키를 발급받고, 모든 WS 메시지는 해당 키로 서명. 서버는 디바이스 키를 검증만 하고 평문 저장 X. 명령 실행 권한은 scope(예: shell:~/Projects, browser:*) 단위로 사용자가 직접 관리.

4 · 필요한 데이터 모델

기존 스키마에 붙일 3개 테이블

기존 BotUser·SlashCommand를 유지하면서, 디바이스/실행 개념을 추가합니다.

테이블핵심 필드용도
agent_devices id · ownerUserId · name · osInfo · publicKey · lastHeartbeatAt · status · sharedCommunityIds[] “내 컴퓨터” 레지스트리. Agents 탭의 디바이스 리스트 소스.
device_agents id · deviceId · name · version · scopes[] · defaultVerb · enabled 한 디바이스에 설치된 Agent들. 자동완성 후보.
command_executions id · deviceAgentId · input · channelId? · threadId? · requesterUserId · approvers[] · status · startedAt · finishedAt · stdout · stderr · exitCode 모든 명령의 감사로그. 재실행·Inbox·Device Dashboard가 이걸 읽음.
