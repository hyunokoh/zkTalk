# zkTalk bug report — 2026-04-25

Targeted hunt over `apps/web/src/` after the bulk sed palette to semantic-token
refactor (commits `a0dbc5b`, `f7f0f4b`) and the theme-toggle commit `db45e7e`.
Findings are grouped by priority. Every bullet gives `file:line`, what is wrong,
and a one-line fix.

Important cross-cutting pattern discovered — sed collapsed pairs like
`bg-indigo-600 hover:bg-indigo-700` to `bg-accent hover:bg-accent`. The hover
state is now the same color as rest, so every primary button has a dead hover.
Same pattern for `bg-danger hover:bg-danger`, `bg-warning hover:bg-warning`,
`bg-bg-hover hover:bg-bg-hover`, `bg-bg-subtle hover:bg-bg-subtle`,
`text-fg-muted hover:text-fg-muted`. I've listed the worst offenders below;
there are dozens of each and they should be swept en masse.

Second cross-cutting pattern — many `text-white` classes survived into places
where the new background is a light token (`bg-bg-subtle`, `bg-bg-hover`,
`bg-bg-elevated`). In light mode they render white-on-white. They should be
`text-fg` (or `text-[color:var(--on-accent)]` on accent surfaces).

Third pattern — `dark:` variants that point to a token which already auto-flips
in CSS (e.g. `text-fg dark:text-fg-muted`, `bg-bg-subtle dark:bg-bg-subtle`).
The former actively inverts contrast in dark mode; the latter is dead code.

### Summary

- P0: 16 bullets — mostly "unreadable text" regressions (white text on light surfaces, same-color text-on-same-color) and the opaque backdrop on OnboardingModal.
- P1: 25 bullets — dead hover states (40+ files each bucket), surviving raw palette classes (slate, gray, placeholder-gray), broken dark: inversions (63 instances across 17 files), Agent-device UI hardcoded English.

- `\bhover:bg-danger\b` → `hover:bg-danger/85`
- `\bhover:bg-bg-hover\b` where class already contains `bg-bg-hover` — drop it
- `\bhover:bg-bg-subtle\b` where class already contains `bg-bg-subtle` — drop it
